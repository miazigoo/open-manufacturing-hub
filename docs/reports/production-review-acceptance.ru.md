# Приёмка Open Manufacturing Hub, 19 ноября 2026

Проверена рабочая копия на базе 6d127f2 с незакоммиченными исправлениями. Вердикт — можно начинать контролируемый пилот. Данные, пользователи и PostgreSQL для проверок были тестовыми.

| Область | Проверка и результат |
|---|---|
| Доступ к интерфейсу | Chromium прошёл вход через production nginx и открыл журнал. Запросы интерфейса шли на тот же origin. |
| Очередь | На 50 000 строк получены две последовательные страницы по 50 записей без повторяющихся ID. Новый список получает краткое представление, прежний API сохраняет выдачу payload по умолчанию. |
| История и повтор события | Браузерный сценарий создал 25 запусков, открыл самый старый, изменил данные для повтора и дождался 26-го запуска. Исходный артефакт сохранился. До явного открытия содержимое артефакта не запрашивалось. |
| Запуск и миграции | Production Compose поднялся с нуля. PostgreSQL 16 прошёл миграции до 0039. В dev-сборке проверено горячее обновление интерфейса. |
| Доступность | При остановленном worker и устаревшей отметке активности readiness вернул 503, liveness — 200. После запуска worker readiness вернулся к 200. |
| Восстановление | SQL и custom dump восстановлены в отдельные БД PostgreSQL 16. Контрольная запись совпала. Попытка занять существующее имя и повреждённый дамп завершились ошибкой. Исходная БД сохранила и запись, добавленную после бэкапа. |
| Автоматические проверки | В чистой копии прошёл make release-check-local, включая 440 backend-тестов, сборку frontend с проверкой TypeScript, проверки OpenAPI, маршрутов и официальных пакетов. Отдельно прошёл браузерный smoke. |

Штатные команды также проверены в изолированном production-профиле. Копия из API прошла make prod-restore-drill с проверкой контрольной суммы и удалением временной БД. SQL-копия из make prod-backup прошла make prod-restore с сохранением восстановленной БД.

## Загрузка первой страницы

Стенд содержал 100 000 событий и 50 000 записей очереди. Заполнялись исходные и текущие данные объёмом по 4 КиБ. Для каждого сценария выполнены 20 прогревочных и 200 измеряемых авторизованных запросов, до десяти одновременно.

| Запрос | p50, мс | p95, мс | Размер ответа, байт |
|---|---:|---:|---:|
| Очередь, первая страница | 66,6 | 153,4 | 38 016 |
| Журнал, первая страница | 71,2 | 166,4 | 35 168 |
| Поиск конкретной старой записи в журнале | 69,0 | 120,7 | 747 |

Это время ответа API на прогретом стенде. Для оценки рабочего места оператора нужно измерить время до появления доступных для взаимодействия строк в браузере через сеть предприятия.

## Условия выхода из пилота

1. Провести один полный обмен на целевом контуре 1С или оборудования и сверить результат на обеих сторонах. Повторить со сбоем после приёма сообщения внешней системой и проверить отсутствие двойной операции.
2. Повторить нагрузочный профиль из ТЗ с реальным распределением запусков, шагов и инцидентов за 90 дней. Замерить интерфейс с холодным кешем.
3. Провести с оператором переключение приложения на восстановленную копию, измерить простой и возраст последней восстановленной записи и сравнить с требованиями площадки.
