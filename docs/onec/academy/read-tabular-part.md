# Читаем табличную часть документа 1С через OData

Этот урок относится к `/master` Step 2B. Он отвечает на один вопрос:

```text
Я нашёл документ 1С. Как прочитать его табличную часть?
```

## Что такое табличная часть

В документах 1С есть вложенные строки: товары, продукция, материалы, услуги. В OData они читаются как вложенный resource объекта.

Для заказа производства пример выглядит так:

```text
Document_ЗаказНаПроизводство2_2(guid'{{order.Ref_Key}}')/Продукция
```

`Document_ЗаказНаПроизводство2_2` — базовый resource документа.

`guid'{{order.Ref_Key}}'` — ссылка на найденный документ.

`Продукция` — табличная часть документа.

## Почему нужен Ref_Key

На Step 2A OMH нашёл заказ и сохранил его как `order`:

```json
{
  "Ref_Key": "c3335ee4-43d0-11f1-8388-000c29b755c7",
  "Number": "260666/6938",
  "Date": "2026-04-29T16:38:53",
  "Posted": true
}
```

`Ref_Key` — внутренняя ссылка 1С на объект. Для чтения табличной части документа обычно нужен именно `order.Ref_Key`, а не номер документа.

## Настройка Step 2B

В `/master` после сохранения Step 2A выберите:

```text
Шаг 2B — Чтение табличной части объекта 1С
```

Заполните поля:

```text
Какой объект 1С читать: order
Поле ссылки 1С: Ref_Key
Тип ключа: GUID
Базовый OData Resource: Document_ЗаказНаПроизводство2_2
Табличная часть / вложенный ресурс: Продукция
Какие поля получить: Номенклатура_Key, Количество, КоличествоУпаковок
$top: 100
Загружать следующие страницы: false
Сохранить строки как: products
Ошибка, если строк нет: true
```

## Preview

Template resource:

```text
Document_ЗаказНаПроизводство2_2(guid'{{order.Ref_Key}}')/Продукция
```

Rendered resource:

```text
Document_ЗаказНаПроизводство2_2(guid'c3335ee4-43d0-11f1-8388-000c29b755c7')/Продукция
```

Template использует переменную. Rendered показывает реальный resource на sample данных из предыдущего OData test.

## Test result

Ожидаемый результат:

```json
[
  {
    "Номенклатура_Key": "ff22288c-2da4-11f1-8388-000c29b755c7",
    "Количество": 180,
    "КоличествоУпаковок": 180
  }
]
```

OMH сохранит массив как:

```text
products
```

Будущие переменные:

```text
products[]
products[0].Номенклатура_Key
products[0].Количество
products[0].КоличествоУпаковок
```

Следующий будущий шаг сможет пройти по `products` и выполнить OData-запрос для каждой строки. Foreach не входит в Step 2B.

## Empty result

Если включено `Ошибка, если строк нет`, пустая табличная часть вернёт:

```text
ODATA_TABULAR_PART_EMPTY
```

Что проверить:

- Step 2A действительно нашёл правильный `order.Ref_Key`.
- `Ref_Key` выглядит как GUID.
- Базовый resource соответствует документу.
- Табличная часть называется точно `Продукция`, а не `Товары` или другое имя из конфигурации.
- Пользователь OData имеет права читать табличную часть.

## Что не входит в Step 2B

- foreach по `products`;
- поиск кодов по каждой продукции;
- JSON builder;
- XML builder;
- endpoint send;
- сохранение полной интеграции;
- Timeline.
