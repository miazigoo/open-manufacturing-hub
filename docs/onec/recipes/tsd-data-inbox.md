# Рецепт: приемник данных для ТСД и устройств

## Когда использовать

Нужно принимать данные с ТСД, весов, лазерной станции или другого устройства,
не привлекая разработчика. Оператор сам описывает шаблон: какие поля
обязательны, что делать если их нет, хранить ли данные и сколько, что ответить
устройству.

## Как это работает

```text
ТСД -> OMH: POST /api/inbox/<slug шаблона>
OMH: проверяет обязательные поля и типы по шаблону
OMH: отклоняет с понятной ошибкой ИЛИ принимает (с предупреждением/умолчанием)
OMH: сохраняет запись (если шаблон говорит хранить) и пишет событие в Timeline
Оператор: смотрит записи, фильтрует, правит, удаляет, шлет повторно, экспортирует
```

## Настройка шаблона

Страница `Приемник (ТСД)` -> `Новый шаблон`:

1. **Поля данных**: путь, тип, обязательное, значение по умолчанию.
2. **Если нет обязательного поля**: отклонить с понятной ошибкой / принять с
   предупреждением / подставить умолчание.
3. **Хранение**: не хранить / N дней / всегда. Очистка по сроку выполняется
   штатным retention.
4. **Токен доступа**: если задан, устройство обязано слать `X-OMH-Token`.
5. **Шаблон ответа**: JSON с плейсхолдерами `{{record.id}}`, `{{fields.*}}`,
   `{{record.status}}`.

Endpoint готов сразу после сохранения: `POST /api/inbox/<slug>`.

## Управление записями

Вкладка `Записи`: фильтры по шаблону, статусу (сохранено / принято с
предупреждением / отклонено) и поиск по данным. Запись можно открыть,
отредактировать, удалить, отправить повторно на URL и выгрузить в CSV.

## SQL-консоль

Страница `SQL-консоль` — запросы к базе OMH только на чтение (SELECT).
Запрещенные слова (INSERT/UPDATE/DELETE/DROP/...) и мультистейтменты
блокируются с понятной ошибкой. Результат — таблица + экспорт CSV.

## Бэкапы по пути

Страница `Production` -> `Бэкапы базы данных`: укажите папку на сервере OMH,
нажмите `Сделать бэкап БД` — файл `omh-db-<дата>.dump` появится в папке и в
списке, откуда его можно скачать. Папка задается переменной `BACKUP_DIR`
текущего environment или env `OMH_BACKUP_DIR`.
