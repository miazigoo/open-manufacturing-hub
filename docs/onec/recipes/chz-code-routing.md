# Рецепт: маршрутизация кодов ЧЗ по правилам

## Когда использовать

1C отправляет пул кодов в OMH. По умолчанию весь пул сохраняется в локальный
архив, при необходимости копируется на SMB-шару лазера и отправляется в DnP.
Правила маршрутизации позволяют разделить пул по ключам (GTIN, серийный номер,
номер заказа) и отправить разные части в разные места — без программирования.

Примеры:

- коды одного GTIN — на лазер линии 1, остальные — как обычно;
- коды конкретного заказа — только во внешний HTTP-сервис;
- коды с серийником по шаблону — в отдельный файл с собственным именем.

## Как это работает

```text
1C -> OMH: пул кодов
OMH: для каждого кода проверяет правила по приоритету (меньше = раньше)
OMH: первое совпавшее правило забирает код в свой сегмент
OMH: коды без совпадений -> default-сегмент (поведение как раньше)
OMH: каждый сегмент -> локальный архив (всегда) + цели правила
```

Цели правила:

- `laser_file` - записать файл сегмента на SMB-шару лазера (даже если
  глобальная копия для лазера выключена; SMB UNC при этом должен быть настроен).
- `http_forward` - отправить сегмент в произвольный HTTP-сервис
  (`name`, `url`, опционально `header_name` + `token`, `timeout_seconds`).
- `file_name_template` у любой цели - свой шаблон имени файла сегмента.

Локальный архив пишется для каждого сегмента всегда - это страховка и основа
для retry.

## Настройка через UI

Страница `Пулы кодов ЧЗ` -> вкладка `Маршрутизация`:

1. `Новое правило`: имя, приоритет, условия (поле - оператор - значение).
2. Цели: чекбокс `Файл для лазера (SMB)` и/или HTTP-цели.
3. `Проверить на примерах`: вставьте несколько кодов и посмотрите, какое
   правило какой код заберет.
4. Вкладка `Тест`: предпросмотр показывает разбиение пула на сегменты.
5. `Журнал экспортов`: каждый сегмент - отдельная строка со своим статусом и
   retry.

## API

```http
GET/POST /api/marking-code-pools/routing-rules
GET/PATCH/DELETE /api/marking-code-pools/routing-rules/{id}
POST /api/marking-code-pools/routing-rules/test
```

Пример правила:

```json
{
  "name": "GTIN 04646 на линию 1",
  "priority": 10,
  "enabled": true,
  "match_json": {
    "mode": "all",
    "rules": [
      {"type": "body_path_starts_with", "path": "gtin", "value": "04646"}
    ]
  },
  "targets_json": [
    {"type": "laser_file"},
    {"type": "http_forward", "name": "Line1", "url": "http://line1.local/codes"}
  ]
}
```

Поля для условий: `gtin`, `serial`, `code` (полный код), `order_number`,
`source_document_id`, `source_system`. Операторы: `body_path_equals`,
`body_path_not_equals`, `body_path_contains`, `body_path_not_contains`,
`body_path_starts_with`, `body_path_ends_with`, `body_path_in`,
`body_path_not_in`, `body_path_gt/lt/ge/le`, `body_path_regex`,
`body_path_exists`. Группы: `mode: all|any|none`, вложенность до 3 уровней
через `{"group": {...}}`.

## FAQ

- Что если ни одно правило не совпало? Код уезжает в default-сегмент и
  обрабатывается по глобальным настройкам, как раньше.
- Что если правил нет вообще? Поведение побайтово прежнее: один файл, одни
  действия.
- Порядок правил: по возрастанию `priority`, первое совпадение выигрывает.
- Retry: у каждого сегмента своя строка в журнале; `Повторить отправку` шлет
  сегмент в его HTTP-цель (не в глобальную).
